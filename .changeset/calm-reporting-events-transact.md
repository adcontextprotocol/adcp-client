Add a transactional PostgreSQL reporting lifecycle activity bridge with schema-conformant health notifications, finality-aware account activity, stable event identity, fenced crash recovery, tenant-scoped pagination, and reuse of persistent notification webhook delivery. Finality-only lifecycle transitions are newly recorded for internal activity but do not emit the health-only AdCP webhook. Pre-v14 transitions without a recorded finality resolve their baseline through `ReportingLedgerStore.resolveTransitionFinalityBaseline`, which persists `none` rather than reconstructing one. The lifecycle decision and the store's compare-and-set therefore read one committed baseline. No stored timestamp can prove which revisions had committed when a pre-v14 row was recorded — payload timestamps rank creation rather than commits, and insert wall clocks tie and step backward — and guessing suppresses a real snapshot-to-official change permanently, so upgrades record at most one redundant finality-only internal activity entry instead. The recovery worker now commits each transition's recipient set onto its claimed activity row before any external send and replays that committed set through the new `NotificationEvent.freezeRecipients` barrier, so a crash between send and settlement followed by a subscription replacement can no longer deliver the same notification again under a new destination generation and idempotency key. `REPORTING_LEDGER_FINALITY_WRITER_FENCE_MIGRATION` adds a `NOT VALID` check constraint that permits historical rows but rejects any new transition lacking a recorded finality, making the one-redundant-event-per-obligation upgrade bound enforceable against a pre-v14 writer that survives a rolling deploy. Operational delivery-authority failures (`authorization_error`, `credential_unavailable`, `subscription_stale`) are now classified by the exported `notificationSuppressionDisposition` and release the recovery claim instead of settling the activity as delivered, so a transient store, authorization or credential failure no longer silently drops a notification. A second barrier, `NotificationEvent.beforeExternalAttempt`, records the moment an external POST begins, which makes the frozen recipient set revisable until then — closing the window where a destination replacement lands between candidate enumeration and the first POST — and immutable afterwards. Recipient intent is stored relationally in `<activity_table>_recipients` keyed by intent round, so a maximum fanout of maximum-length references is storable without a serialized-document size cap that could poison a claim; `maxRecipients` defaults to the notification runtime's 10,000 ceiling and unstorable configurations are rejected at construction. Delivery authority, attempt recording and settlement are now tracked per recipient. `PersistentNotificationRuntimeOptions.checkpointDeliveryAttempt` replaces the per-emission barrier so recovered outbox attempts — which are rebuilt from a durable snapshot and cannot carry a closure — record the same durable pre-POST checkpoint; wire `createPostgresReportingNotificationAttemptCheckpoint()` into it and `probe()` fails closed if it is missing. A retryable suppression releases its webhook outbox entry instead of terminalizing it, and projection now requires every stored recipient to have reached a terminal disposition, so an outcome that never reached a subscriber can no longer settle the activity as delivered. Pinning is keyed on the subscriber rather than the destination generation, so one recipient's attempt never freezes a sibling suppressed before its own first POST, and unattempted rows are replaced in place so pre-attempt retries cannot accumulate. Finally, a custom store that implements neither the finality baseline port nor the optional finality fields no longer writes a finality-only transition on every reconciliation tick. The durable pre-POST checkpoint is scoped to the event types it owns so an unrelated notification is passed through rather than suppressed until its retry horizon; a partial unique index on the attempted subscriber serializes a checkpoint racing a recipient replacement so only one generation can ever be addressed; `maxRecipients` now bounds every retained row before the write and settled history is compacted to one row per subscriber; a retired delivery binding or exhausted retry horizon is preserved as terminal and settles the activity instead of holding it pending; the activity runtime fails closed at construction and at `probe()` unless the notification port proves it runs the checkpoint; and `subscription_stale` is terminal for a generation-pinned recovered attempt while staying retryable for a live emission that can re-resolve. Recipient-bound enforcement and recipient replacement are now one statement whose measured rows are taken `FOR UPDATE`, so a concurrent checkpoint can no longer push the retained set past the bound, compaction runs before any refusal, and a refusal mutates nothing. The checkpoint's `eventTypes` extends its mandatory ownership of `reporting.status_changed` instead of replacing it. And the freeze is verified rather than trusted: a port that declares checkpoint support but never calls `freezeRecipients` is refused instead of projecting an unsent notification as delivered.

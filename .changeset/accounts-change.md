Add `client.accounts.change(accountId, changes, { revision, allowSeparateAccount })`, which changes an account through AdCP 3.3 `request_account` with `account_id`. It resolves to an `AccountChangeOutcome`: `updated` (with `revision` and `effective_at`), `separate_account` (with `not_carried_over` and `subscriptionsNotCovering`), `matched_existing`, `pending`, or `rejected` (with `requiresNewAccount`). A money change (`billing`, `billing_entity`, `payment_terms`) without `revision` is refused before dispatch with `AccountRequestError` code `ACCOUNT_REVISION_REQUIRED`. Other changes read the revision from `list_accounts` and retry once on `CONFLICT`, but only when the changed fields did not move. Unknown attributes (`ACCOUNT_CHANGE_INVALID`) and sellers without `account.requests` (`ACCOUNT_REQUESTS_UNSUPPORTED`) are also refused locally, and the error carries `dispatched: false`. A separate or matched account never re-points the registry: `client.accounts.use(key, accountId)` is the explicit step. `client.accounts.changeStatus(accountId, requestId)` reads a pending change back. `nextStep` accepts change outcomes. The behavior matches the Python SDK's `accounts.change`.

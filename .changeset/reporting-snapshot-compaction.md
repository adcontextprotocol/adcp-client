Reliable Reporting: opt-in compaction of superseded snapshot revision content, as permitted by adcontextprotocol/adcp#8100. `PostgresReportingLedgerStore.compactSupersededSnapshots({ statusRetentionDays, automatedRecoveryWindowSeconds, limit?, maxFeedHoldDays?, account_id?, signal? })` drops the row content of superseded snapshots outside the protocol's content-retention rule (never the current or official revision, never the revision the current one supersedes, never inside the recovery grace of `max(automatedRecoveryWindowSeconds, 3600)` seconds, never a revision any caller's receipt or current `received` / `unreadable` / `content_mismatch` statement names while its window is open) while every revision's metadata stays listed. An exact read of a compacted revision returns the same nondisclosing `REFERENCE_NOT_FOUND` as an unknown ID. It reuses retirement's resumable three-phase delete, fenced object deletes, shared-chunk safety, lease, materialization and feed-consumer holds. Enable it with `maintenance: { compaction: { enabled: true, limit? } }` on `createReliableReportingService` or `compaction: { enabled: true, limit? }` on `createPostgresReliableReportingProductionService`; default off. Do not enable it in production before the next eligible AdCP minor after November 20, 2026. `listRevisions` now omits compacted revisions instead of failing; use `listRevisionMetadata` for the full chain.

Server-side callers can stop repeating endpoint, `tools/list` and `get_adcp_capabilities` discovery, and stop opening a new MCP session per call (#3171).

- **Shared discovery cache (opt-in).** `SingleAgentClientConfig.discoveryCache` takes a cache (`createInMemoryAgentDiscoveryCache()` or your own `AgentDiscoveryCache`) and a required, caller-owned `authIdentity`. Instances for the same agent URL, identity, credential kind, AdCP version, non-correlation headers, signing identity and transport policy reuse one endpoint / tool-schema / capabilities observation for `ttlMs` (default 5 minutes), with in-process singleflight for concurrent cold clients that keeps each caller's own signal and deadline. Synthetic capabilities and scoped `trustedFetchFn` calls are never shared, entries are cloned, and backend failures or hangs cost a rediscovery rather than a failed call. `invalidateDiscoveryCache()`, `primeDiscoveryCache()` (also on `AgentClient`), `refreshCapabilities()`, a failed feature check against shared evidence, and seller version/capability errors invalidate. `primeCapabilities` stays client-bound and unchanged. See `docs/guides/DISCOVERY-CACHE-AND-SESSION-REUSE.md`.
- **Connection identity excludes per-call concerns.** The MCP connection key (modern, v1 and OAuth paths) no longer includes correlation headers (`traceparent`, `tracestate`, `x-request-id`, `x-correlation-id`, `x-trace-id`, `x-*-debug-id` and similar), the caller's `AbortSignal` or `requestTimeoutMs`. Each call still sends its own correlation headers, deadline and cancellation on every request over a shared session, including concurrent calls. A cancelled or timed-out call no longer evicts or terminates a session other calls are using, and a caller joining another caller's in-flight connect retries a creator-cancelled connection under its own signal and timeout (up to two foreign-abort retries). Tenant and routing headers, `baggage`, credentials, signing identity, `allowPrivateIp` and a caller-injected `fetchFn` still isolate connections.
- **Behavior changes to audit.** Calls that pass a signal or timeout outside a connection scope now reuse the process-wide session cache instead of opening a one-shot session (only a caller-injected `fetchFn` stays one-shot); the v1 path now treats `baggage` as connection identity; an explicit caller `traceparent`/`tracestate`/`baggage` header now wins over ambient OpenTelemetry context; v1 era classification now outlives a connection scope within its TTL.
- **Public connection scope.** `withMCPConnectionScope` and `closeScopedConnections` are exported from `@adcp/sdk` and `@adcp/sdk/advanced`. `closeScopedConnections()` is a no-op outside an MCP scope; `closeConnections()` from `/advanced` provides explicit global shutdown. The legacy/OAuth process-wide caches retain their 20-entry LRU bounds. Inside a scope the endpoint probe, `tools/list` (including for legacy-era sellers) and tool calls share one session per identity, terminated once at scope exit. The first call against a legacy-era seller still costs one extra classification handshake.
- **Cache correctness hardening.** `require()` and the pre-flight check both re-decide a missing feature on live capabilities before refusing; a seller capability error invalidates shared evidence on every task path; invalidation leaves a bounded in-process tombstone and epoch so another instance's local capabilities and endpoint, and a backend entry whose delete failed or is still queued, are not reused; per-key backend mutation queues are bounded (unstarted abandoned writes are dropped, invalidations behind a hung delete coalesce, nothing replays) and a `primeDiscoveryCache()` timeout is documented as an unconfirmed, not empty, outcome. Ambient OpenTelemetry baggage now partitions the discovery key like any other non-correlation header.

Endpoint URLs with userinfo, a query string or a fragment are never stored in shared discovery evidence; they remain local and cannot be passed to `primeDiscoveryCache`. Capabilities and schemas for those endpoints can still be shared.

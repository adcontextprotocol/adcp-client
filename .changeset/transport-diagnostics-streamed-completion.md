Transport diagnostics now report how streamed responses finish. When a response body is not captured (SSE, no finite `Content-Length`, non-text, or over the capture limit), `wrapFetchWithTransportDiagnostics` passes the body through an observing stream, with the same bytes, status, headers, `url`, `redirected`, and `type` and with unchanged backpressure, and emits one `response_completed` event with `outcome` (`ended`, `errored`, `aborted`, or `cancelled`), total `bytes`, and `durationMs` from `startedAt`. The event is fire-and-forget: the diagnostics scope never waits for it, and it carries no request or response bodies. `response_received` is now documented as "headers received" (`durationMs` is time to headers); completion can arrive after the diagnostics scope exits. It sets `streaming: true` when a `response_completed` event will follow. Public `TransportActivityType` and `TransportResponseOutcome` aliases describe the events and terminal outcomes. `TransportActivityType` and `TransportActivity` gain `response_completed`, `outcome`, `bytes`, and `streaming`; exhaustive switches over `TransportActivityType` need a new case, and handlers that treat every non-`request_started` event as a response need to check `type`. The `Response` returned for an uncaptured body is a new object that preserves status, headers, `url`, `redirected`, and `type`.

# SDK 17.0.0-beta.0

SDK 17's first beta targets the signed AdCP `3.3.0-beta.0` release. Install with `npm install @adcp/sdk@17.0.0-beta.0` for development and staging. npm `latest` remains on the stable SDK 16 line.

- **AdCP 3.3 types and validation.** Generated from the published beta bundle, including optional catalog ingestion, onboarding, identity, DOOH inventory, audience and creative metadata.
- **New discovery tools.** `listCollections()` and `listProposals()` are available on typed clients and optional server/platform handlers, with typed completion callbacks.
- **Exact beta negotiation.** The seller must advertise the selected preview. Other beta versions and moving family aliases do not imply compatibility. Stable AdCP 3.2.7, 3.1.29 and 3.0.25 schema/compliance bundles remain packaged.
- **Account discovery.** Served 3.3 requests refuse unresolved account references before calling a handler. Discovery must not provision or activate accounts.
- **Breaking creative mapping (#3361).** AAO HTML-markup formats now resolve to `display_tag` with inline-markup delivery. Legacy writes preserve markup bytes and seller format identity; actual `html5` zip creatives no longer match markup-only products.

Review the [16 → 17 migration guide](../migration-16-to-17.md), including changed helper return values, evaluator URLs, new asset variants and account-resolution requirements. The identity/Web Bot Auth opt-in and reporting storage APIs retain their experimental status.

Protocol provenance and the release checklist are in the [SDK 17 adoption record](https://github.com/adcontextprotocol/adcp-client/blob/main/docs/development/v17-beta-plan.md).

The standalone commercial-terms verifier fails closed on the new definition-pin flows until current-source verification is supported; see the migration guide.
